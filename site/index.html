How points work

The number next to a name is only activity in the selected window (past 7 or 14 days) — not career total. A score like 326 usually means “a lot of merged PRs this week,” not millions of issue spam points.

Typical merged PR 10–22 pts base 10 + size bonus up to 12 (flattens after ~60 lines)
Substantive review 15–20 pts ≥15 char body · Approved or Changes requested · once per PR
Issue filed / closed +2 / +1 max 8 issue pts / day — filing 100 tickets can’t mint a lead
Same-day PR flood decays after 2 3rd merge ≈ ×0.55, then keeps falling to a 12% floor — so 45 PRs ≠ 45 × 22

Worked example: ~45 merged PRs in a week, many of them on busy days, often lands near 300–350 pts after same-day diminishing returns (avg ~7 pts/PR). One high-quality review (20) is worth roughly as much as two tiny burst PRs that already hit the decay floor — by design.

Pull requests

Only merged into main or master. Lockfiles / generated / vendored paths are excluded from size. Volume farming is damped after 2 merges/day.

Reviews

Only Approved (+20) or Changes requested (+15) with a real body (≥15 chars). No self-reviews. One scored review per PR. Bots never appear.

Issues

+2 to open (valid), +1 when completed. Rejected as duplicate, wontfix, invalid / not-planned score nothing. Burst decay after 2/day. Hard cap 8 issue pts/day.

Humans only

Dependabot, GitHub Actions, Renovate, [bot] accounts, and named agents (e.g. MantisCartography) are excluded. Rankings track who’s actively shipping now.

Ranked by points in the selected window only — not lifetime totals.
Why a score looks “small”: same-day PR floods are discounted; issues hard-capped. Hover a total to see the split.
